# S1 资源读取 · S2 需求识别

## S1 资源读取

目标：把用户手里的一切变成一份**材料登记**，并列出缺口。保存由 `execution-contract.md` 决定（概念模式只做 §1.2b 轻量登记）。

### 1.1 读什么

| 资源类型 | 读取要点 | 登记为 |
|---|---|---|
| 世界观 / 设定文档 | 时代、地点规则、技术/魔法约束、社会关系、禁忌 | `<ip>/ip.md` 世界观 |
| 角色小传 | 外观（可观察：年龄段、体型、发型发色、肤色、标志性服饰/配饰/疤痕）、说话方式（语速、口头禅、方言、音色）、欲望与恐惧、与他人的关系 | `<ip>/ip.md` 人物总表 |
| 场景 / 地点 | 空间布局（入口、窗、光源方向、主要陈设）、时刻与天气、声音环境 | `<ip>/ip.md` 地点总表 |
| 剧本 / 大纲 / 一句话想法 | 场景目标、冲突、已有台词 | S3b / S3c 输入（已有剧本时作为体检对象） |
| 生产参考素材（参考图 / 参考视频 / 音频 / 已有成片 / 分镜图） | 只列清单与用途线索，不登记参考职责 | 素材清单（交接时随材料一并指认给 film-director） |

### 1.2 登记规则

- **登记可观察信息**：人物外观与说话方式写成可观察量（识别性细节），供剧本与后续生产共用；地点写空间关系与声音环境。
- **来源与锁定分开记**：用户给的设定、用户确认的内容、模型推断的假设分列；假设可推翻，锁定不擅改。
- **生产职责不在此裁决**：素材"参考什么 / 不参考什么"、上传编号与外观锁重写由 film-director 在其资产登记中处理。

### 1.2b 概念模式的轻量登记

概念模式按执行契约保存，默认对话交付。内部按需记原始需求、目标格式/时长、核心情绪或类型、已有素材；不强制回显四行。开启保存时写入已有 `00_brief.md`。有素材时走 `stage-3a-concept.md` 的素材入口。

### 1.2c 已有故事的上下文读取

续写、扩写、加戏或改稿时按 `story-context.md` 读取当前采用的整体故事、目标场、相关前后文及远处依赖；不能把最后一轮对话当全故事。已保存项目先核版本，摘要只作导航；提取本场有效依据后进入正文，不要求补齐所有上游文档。

### 1.3 缺口清单

读完后列出：
- 缺失且不可替代的：角色处境与关系、事件前因后果、台词语言。→ 仅当影响本次交付且无法合理补足时询问；已授权虚构人物可创作，不将缺外观变成故事前置门槛。
- 缺失但可推断的：时刻、天气、光源、声音环境。→ 仅在已有故事未锁定、且属于可创作空间时补足；必要假设按保存契约记录。

## S2 需求识别

一句话产出：**创作意图 / 材料成熟度与入口 / 锁定项 / 自主度 · 确认 · 保存 / 场景参数**。内部复用识别结果；有保存约定时写入 `00_brief.md`，无需逐次向用户展示。

### 2.0 创作意图与三个独立轴

先读 `execution-contract.md`：确定交付终点、排除项、材料成熟度、硬锁、自主与保存。意图包括想故事、发展已有想法、写完整剧本、局部改写及只保存；进入生产与表演测试是越界项，指认材料交 film-director。脚本用 `scripts/route_check.py --record …` 验证模型形成的结构化判断，不按原文关键词猜测。

### 2.1b 场景参数提取

从需求独立提取六参数（强度 / 方向 / 信息 / 权力 / 进场温度 / 密度，`scene-parameters.md` §一）；角色情绪强度与克制分别记录，不从"高"推断外放或密集台词，开启保存时写进 `00_brief.md`，在需要决定时简短回显。需求线索优先于缺省；线索冲突两者保留；提取不到且实质影响结果时在第一个停靠点问一次。

### 2.1c 创作判断（从想法开始的任务）

从想法或概念开始时，在参数之外写四行简短判断（可暂定，允许通过试写再改，不要求用户填表）：观众最初会怎样理解这件事 / 我们希望他们最后怎样理解人物 / 本作最值得保留的独特之处 / 哪些是用户锁定、哪些允许探索。按保存约定记录，不强制向用户展示四行；S3a 用它选入口（`concept-generation.md` 第 0–2 步），后续停靠点用它检查"最初吸引人的东西还在不在"。

### 2.2 入口：按材料成熟度，不按表面形式

入口由材料的实际成熟度决定。文本里出现台词不等于剧本已完成；有场景表不等于故事已完成；有主题句不等于概念已完成。对每份材料判断三件事：人物是否有具体处境与关系；事件是否有前因后果；用户是否已表示这部分"定了"。

| 用户已有 | 成熟度判断 | 入口 |
|---|---|---|
| 只有题目、情绪或关系 | 无人物无事件 | S3a 想故事 |
| 一句话想法、一个人物、一段对白或片段 | 有生命力的局部，人物与事件未展开 | S3b 发展已有想法：先试写最有生命力的部分，再长出人物与事件；概念判断可回写，不强制先做概念卡 |
| 大纲或故事正文（人物、事件、结尾清楚） | 故事成熟 | S3c 写完整剧本；故事锁定沿用 |
| 剧本（完整场景，台词由用户确认已定） | 剧本成熟 | 创作侧无缺口：指认材料，生产由 film-director 承接 |
| 带台词的草稿，但场景为什么发生、人物为什么这样说不清楚 | 剧本未成熟 | 先按 `character-scene-development.md` §五 定位缺口在场景 / 人物 / 交流 / 措辞哪一层，再决定回 S3b 还是 S3c；用户说"台词就这样"时锁定台词 |
| 剧本无台词且用户要台词 | 需要 S3c | S3c，故事部分不重停 |
| 已有文本 + 具体批评 | 局部改写 | `creative-loop.md` §二 诊断层级 → 定点重写 |
| 镜头表 / 分镜 / 成片 + 问题描述 | 进入生产 | 越界项：指认材料交 film-director |

成熟的部分锁定沿用，不重复补上游；不成熟的部分回到相应成果类型补，并在停靠交付里说明"这一部分按未定处理，因为 __"。

### 2.4b 项目目录（一个 IP 一个目录，一个故事一个子目录）

```
<workspace>/<ip-slug>/
  ip.md                    世界观、人物总表、地点总表、视觉声音总则（跨故事）
  <story-slug>/            一个故事、一条先导、一集
    00_brief.md
    01_concept.md          概念选定后才写
    02_story.md            故事文档（按保存契约）
    03_script/scene-XX.md  剧本页（按保存契约）
    project-state.json       当前版本、确认快照、依赖、未决项（保存项目按需）
```

slug 规则：ip-slug = 用户给的 IP 名，或概念选定后的标题；story-slug = 格式 + 标题（`teaser-30s-举证`、`ep01-…`）。**目录按保存契约按需创建；保存候选无需先选定。** 用户已有目录结构时沿用，不新建平铺的阶段目录；同一项目的 04_shots 及之后的子目录由 film-director 生成。

### 2.5 `00_brief.md` 结构

```
# Brief
## 原始需求（原文粘贴）
## 需求识别
- 创作意图：
- 材料成熟度与入口：
- 自主度 / 确认 / 保存：
- 目标格式（时长 / 画幅 / 语言，供生产参考）：
- 场景参数：强度 · 方向 · 信息 · 权力 · 进场温度 · 密度
## 创作判断（从想法开始时；可暂定）
- 最初理解：
- 最后理解人物：
- 最值得保留：
- 锁定 / 探索：
## 假设（可推断项）
## 待用户提供（不可替代项）
```
