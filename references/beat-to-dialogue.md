# 节拍草稿 → 台词：用户给"谁说了什么意思"，交付"这句怎么说"

实际生产里最常见的输入不是故事正文，而是一段**中文节拍草稿**："A 走后，B 对 C 说 xx 意思（打抱不平），C 略不舒服地把话叉开，B 补一句 yy，C 不回话、表情回应，换场。"要求成英文（或目标语言）台词。本文件是这种输入的默认路径；它建立在 `dialogue-design.md`（写连续交流、从听者修订）之上，只补实际反复出错的四件事：承接断了、句子在向观众解释、缺每句说法与情绪递进、缺收尾句。

## 0. 先接上下文（两行，写在正文前）

- **上一场留下什么**：关系 / 信息 / 物件 / 情绪温度 → 本场第一句从这里长出来。
- **本场交给下一场什么** → 最后一句或最后一个动作把它交出去。

来源按 `story-context.md`：账本相邻镜、场景页、`ip.md`。没有这两行，用户最常见的否决是"没有交代叙事、承上启下"。

## 1. 逐节拍定"这句要做什么"

把草稿里每个节拍翻成：**说者 → 听者 · 目的动词（及物：戳 / 挡 / 试探 / 宣布 / 示好 / 打圆场 / 收买）· 听者接住什么 · 这句让局面变了什么**（信息 / 关系 / 位置 / 决定）。

- 一句只为让观众知道背景而存在 → 给它一个此刻需要这条信息的在场听者，或删（`character-scene-development.md` §五）。
- 草稿里用户给的**意思**（"打抱不平""不舒服""嚣张不了多久"）是**意图锁**：措辞可换，意图不换；用户逐字给的英文是**台词锁**，逐字保留。
- 人物所知：这个人此刻知道这件事吗？（早知 / 刚知 / 不知 会改变同一句的写法。）
- 引擎在场吗：这场戏碰到了系列引擎（`series-engine.md`）还是只在私人线上？只在私人线上时写明，不静默滑走。

## 2. 写目标语言台词，再写中文对照

- 先按角色声音写英文（`dialogue-craft.md` §语域 · 声音 · 双语），再给中文对照；不要先写中文再直译。
- 一句一个动作；短句优先但不碎；允许直说。
- 去掉"漂亮但要解释"的比喻：用户否决过"钥匙 / 名字能敲开门 / 钱比建筑老"这类线——听者在 1 秒内不能落地的比喻不用。
- 引擎词汇（组织名 · 赛事名 · 规则名 · 头衔）按 `ip.md` 正典逐字统一，不临场发明近义词。
- 长发言（宣布 / 训话 / 告白）写**情绪阶梯**：3–7 步，每步落在一句上（例：平静立规 → 逐件加压 → 亮权 → 施恩 → 抽底 → 亮牌 → 轻松封场），阶梯写进设计表的"递进"列。

## 3. 台词设计表（交接生产时默认附）

模板 `templates/dialogue-design-sheet.md`。每句一行：台词 · 目的动词 · 潜台词 · 说法（音量 / 语速 / 停顿 / 重音）· 听者可见反应 · 递进（本句在弧线上的位置）· 收尾标记。它是交接层材料，不进入可连续阅读的剧本正文；film-director 直接把它映射为〔说法〕〔情绪〕与【整体情绪弧线】（`handoff-contract.md` §一）。用户只要故事阅读稿时不附。

## 4. 收尾句（scene button）

每场对白要有收尾：最后一句或最后一个动作让场面合上（回应 · 反转 · 转身 · 举杯 · 一个不回答），或明确写"无收尾，硬切下一场"。缺收尾是被反复要求补的项。

## 5. 交付前自检（一分钟）

- 每句删掉会少什么？说不出来 → 删。
- 有没有一句是在向观众解释？→ 给它在场的听者，或删。
- 有没有听者 1 秒内落不了地的比喻 / 双关？（非母语观众也要过。）
- 说话人此刻知道这件事吗？听者能接住吗？
- 引擎在场吗？如果整场只在私人线上，是有意的吗？
- 台词预算：句数 × 秒 ≈ clip 预算？（英语 2.5 词/s，对白 ≤ 2/3 clip；`handoff-contract.md` §四。）超了先精简，不指望生产侧拉长镜头。（这是**时长适配**；用户要"调节奏"是叙事问题，走 `narrative-pacing.md`，不等于缩句。）
- 遍历 `dialogue-craft.md` 末尾的逐句检查。

## 6. 交付形态与修订

正文：英文台词 + 中文对照，前置两行承接；附：台词设计表；一行说明本场碰到引擎的哪一点。用户批评某句时只改那句与直接牵动句（`creative-loop.md` §三），其余锁定；每次修订给全场全文，不给 diff。
