# 有问题才启动的故事开发操作

S3b/S3c 按具体缺口读取。方法来自一手资料的启发，下面的执行方式是本 Skill 的设计推论，不是作者通用公式，也没有预先证明质量增益。出处见 `screenwriting-traditions.md` §五。

## 关键场试写 → 比较 → 回写

当概念听起来成立，却无法确定人物能否在场内产生值得看的交流或行动时，先写最不确定、最值得拍的那段正文。已有有效片段可直接作为起点；片段仍是探索稿。

试写暴露的问题决定是否换进入方式、人物回应或场内条件，再写实际替代片段。比较时暂时遮住两稿的意图说明：哪句或哪个行动让人物更可信、期待更具体？得到什么，牺牲什么？正文不能证明差别就保留不确定，不编造结论。比较数量与片段长度随问题决定，不成为候选或每场的固定配额。

把发现回写到故事假设或人物本次处境，指出具体改了哪一处；采用的片段直接进入剧本，不先压缩成梗概再凭记忆重写。保留旧稿与有效细节，达到本轮问题的解决条件即停。未确定的探索不修改用户硬锁或共享正典。

## 跨场与跨集：让后果进入下一次行动

出现中段重复、每场单看成立却没有发展时，从已写的选择追下去：人物通常怎样解决问题 → 这次实际获得或失去什么 → 关系、资源或所知如何改变 → 下一次为何不能毫无代价地原样重复。把这些变化写进下一场的实际选择，而不是加一段人物成长说明。先修已有场面的承接，确实需要新事件才增加。

结尾核对前文使这个选择或认识为何成立；人物可以拒绝改变、重复错误、仅得到一次理解。观察性作品与平行叙事核对积累、对照和持续处境，不硬套因果成长弧。

多集先识别持续产生事件的关系或处境，再让前集的选择产生下集要承担的后果。每集本身有可读进展；新一集不能只靠新的误会复位人物。开放结尾也要呈现本集已经发生的后果，钩子不替代发展。本集发现仍按项目正典规则处理，不自动改全局人设。

## 信息顺序实验

只有在观众提前猜完、结尾靠突然补设定或信息时机确实影响体验时才做：先核对同一组事件的真实顺序与人物所知，保持事实和用户锁定不变，实际写一个不同呈现顺序的完整段落（早揭示、晚揭示或同步揭示按问题选）。

只读各稿正文，比较观众在哪里形成期待、哪里改判，以及代价是否是理解困难、失去悬念或削弱人物。选择后回写故事正文，必要时保留一句真实时序说明供连续性检查；不要求另建永久信息表，不默认倒叙或反转优于顺叙。正文没产生预期差异时，不用分析说明替它补出效果。
