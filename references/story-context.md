# 故事上下文：开写前取依据，写完后核后果

用于续写、改写、扩写、加戏、跨场/跨集开发，以及从已有片段继续发展。第一次进入这些任务时读取本文件；每次换场或用户修订后复用下列步骤，不必重读方法文件。从零构思只需区分用户锁定与开放空间，不先造一整套世界观。

这是创作依据核对，不是新的审批或必填表。范围、自主与保存仍由 `execution-contract.md` 裁决；简短任务可以只保留几条工作笔记，用户只要正文时不展示过程清单。

## 1. 先定位本次写的是哪个故事、哪个版本、哪个时点

不能只读用户最后一句“这场再狠一点”。先读本次要求及沿用的授权，再找相关原文：

| 层次 | 读取内容 | 要保住什么 |
|---|---|---|
| 整体 | 当前故事正文/大纲及相关 IP 规则、用户批注 | 核心处境、关系、类型与情感承诺、已定结局、世界限制 |
| 本场 | 目标场全文、触发本场的前文、本场影响的后文 | 为什么此刻发生、人物带来了什么、离场后仍须成立什么 |
| 远处依赖 | 早先埋下的线索、承诺、禁忌、身份/知识来源、后续兑现 | 不能只靠相邻两场判断；远处设定同样约束当前戏份 |

短故事直接连读全稿；长项目先读整体故事/索引，再按人物、地点、事件和伏笔定位有关原文。**项目主表是分镜 / 台词表（xlsx）时，它就是当前时间线正典**：用 `python3 scripts/ledger_view.py <表.xlsx> --from 30 --to 40` 读目标镜前后段与台词，再读 `ip.md`（含正典变更表）；列所有权与同步协议见 `handoff-contract.md` §二、§三。若已有 `project-state.json`，按 `project-state.md` 核对 current 与失效依赖；文件新不等于已采用，drafts 和旧确认快照都不自动取代 current。

摘要用于导航，不能替代关键限定词、锁定台词和实际前后场。遇到“直到/只有/尚未/不能/第一次”等限制，保留适用时点与原文依据；不把“不愿说”压缩成“不知道”。文件名、场号或一句原文即可作为定位，不伪造已读记录。

**缺失材料分两种**：
- 既有事实不知道：先查可访问的对话和文件；仍缺且直接决定本场是否成立，只问缺的那一点，完成不依赖它的部分。若需先试写，标明条件与探索身份，不能声称符合未读全稿。
- 开放空间尚未创作：在授权范围内创造人物行动、对白和细节，无须请用户逐项确认。独立一场戏没有前后文，不要求用户补全剧；按其提供的处境写。

## 2. 压成当前场的有效依据

从已读原文提取本场真正用得上的信息，不搬整本人设表：

```
定位：故事/采用版本；事件时点；本轮可改范围
故事承诺：本作让观众关心什么；本场承担什么（也可为观察、积累、余韵）
不能抵触：相关硬锁、规则、已定事件及各自来源
进场状态：关系/承诺；位置/身体/资源；谁知道什么、误信什么及获知依据
出场边界：后文仍须成立的事实；本场可改变的部分；尚不能兑现的伏笔
开放处与缺口：允许创造什么；哪项既有事实仍未知
```

模板见 `templates/scene-context.md`，按需选字段；这是正文的索引，不是另一份正典。尚未写后文时记录已有方向或“开放”，不能编一个结局再强迫用户接受。

特别分开 **故事事实、人物所知/误信、观众所知**。作者知道真相不等于角色已知；角色撒谎不等于世界事实改变。非线性故事按事件时间核状态，按呈现顺序核观众所知；梦境、戏中戏、不可靠叙述标明所在层，不把其中事件混入客观正典。

## 3. 在边界内发展新戏

先写一句：**本场已有处境为什么值得继续看？** 从尚未承担的后果、未说完的关系、角色可用而未试过的选择出发；具体探索见 `creative-search.md`。不能把“更强烈”直接翻译为新增背叛、绑架、绝症、隐藏身份或规则例外。

每个会改变因果的新设定，核对三个问题：它靠什么成立？此时谁能知道/做到？加入后哪些后场需要改变？

- **可直接创造**：不碰既定事实和后续依赖的场内选择、表达与细节。
- **可回流修订**：更好的发现需要改暂定上游，且本轮授权包含该层，先更新假设/受影响正文，再承接；不能只在说明里说“已铺垫”。
- **不能直接采用**：需要突破范围外硬锁、改世界规则或改已定后果的方案。优先交付边界内有效写法；确有价值的越界想法可简短列为另一条提案，说明代价，不能偷渡进正稿。

同一世界规则可以产生新后果，不等于可以临时加例外。人物可以成长、失控或自相矛盾，但需要当下证据；不能把“符合人设”写成永远只会一种反应。用户明确改了旧设定时，新授权范围内更新并追踪影响，不再要求一次批准。

## 4. 接回整片，再交付

写完读 **相关前文 → 新场正文 → 受影响后文**；必要时回读远处铺垫。核对具体文本，而非用“因果自洽”盖章：

- 世界/时空：规则、时间、位置、伤势、资源有没有无依据改变？
- 人物/知识：动机与关系是否带着前因；关键认知有没有获知途径；观众知道的是否漏给角色？
- 后续/承诺：是否提前花掉后场的首次坦白、相认、揭示；是否让后文重复、失去原因或变得不可能？
- 创作收益：新段实际增加了什么体验或理解；是否只是重复前场、更吵、更惨，或用背景解释掩盖戏本身薄弱？安静、并行与余韵不因没推进主线就被删。

有问题先修本场，必要时在授权内修实际依赖；不为救新戏扩改全剧。受影响但未授权的后场列为待复核，不静默改动，也不谎称整片已一致。

采用后更新的只是 **变化量及其依据**：谁新知道了什么、关系/承诺/资源怎样改变、哪个伏笔兑现/仍开放、影响哪几场。探索稿保留在探索层。保存项目依原保存约定更新正文/索引，本集发现不自动升为跨集正典。

## 5. 换轮、压缩与恢复

每次收到修订或“继续”，先接上当前采用稿及本轮增量，再写；不能沿用已被用户否定的分支。长任务交接只保留：目标与范围、采用版本定位、相关硬锁原文、当前状态及事件时点、开放伏笔、被否定方案及原因、待处理依赖。恢复时回读相关原文；无可访问原文就明确缺口，不从摘要补造。

依据与局限见 `context-creativity-sources.md`。`project_check.py` 只检查文件版本与依赖；任何程序通过都不证明本场已尊重故事语义。
