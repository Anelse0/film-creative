# 创作回路与诊断后重写

流水线是逐级交付的，但创作不是。本文件规定三件事：发现怎样回流、批评怎样定位、重写怎样不伤原稿。适用于 S3a–S3c 及试写回流；生产链路（film-director 的表演、分镜与编译）不受影响。

## 一、允许的回流

| 发现发生在 | 可以回到 | 做法 | 不能做 |
|---|---|---|---|
| 关键场景试写（概念前、概念中或故事中） | 概念（创作判断、候选）、人物与关系、故事假设 | 片段里人物实际的回应方式、注意的东西、场景里让人看下去的点，写回候选或人物；原来的假设不成立时改假设，不改片段迁就假设 | 把片段当剧本交付；把片段当概念卡的插图 |
| 剧本页写不顺 | 场景 / 人物 / 交流 / 措辞，按证据定位 | 解释可能有听者需求；先查人物所知与交流处境，再决定是否回流 | 未诊断就加前史，或在措辞层反复润色 |
| 表演外化时发现 | 人物设计（声音表、绝不会做） | 表演条目揭示了人物控制情绪的方式，写回人物栏，供后续场景使用 | 超出本轮授权改台词或事件，或触碰用户硬锁 |
| 分镜时发现 | 剧本页（空间、物件） | 可见性要求改动作位置或物件；不改事件与台词 | 为镜头好看改人物选择 |
| 成片反馈 | 生产层（film-director 的 S5 / S6 / S7） | 定位到镜头卡；只有确属剧本层的原因才回到本 skill | 借修成片重写故事 |

所有回流保护用户硬锁（`00_brief.md` 及本次要求）；已确认稿是可追溯的版本，不阻止用户新授权的修订，范围按 `execution-contract.md`。回流改动了上游产物时，在交付里说明"这一处因为下游发现改了"。

关键不确定性触发的试写、跨场发展与信息排序操作见 `story-development.md`。这些操作必须产生可比较的正文或实际修订；仅列方法名称、解释预期效果不算执行。

## 二、收到批评后：先诊断，再决定层级

用户说"太假 / 太平 / 不喜欢 / 没意思"时，先定位，不先改：

| 症状 | 最可能的层 | 检查 |
|---|---|---|
| 单场精彩却不属于这部故事 | 整体上下文 | 按 `story-context.md` 查世界规则、人物知识、进场后果与后续承诺；先修本场，不给新戏倒编前史 |
| 逻辑通但没意思 | 观众侧：期待没有被建立或改变 | 观众此刻知道什么、期待什么、哪个证据改变判断（`character-scene-development.md` §一） |
| 反转惊人但人物不可信 | 人物侧：回应方式没有依据 | 他认为发生了什么、为什么选择这种回应；缺材料按 `research-to-craft.md` 补 |
| 台词像同一个人写的 | 人物声音 | 生活语言基础、交流对象、当前状态；方法统一在 character-scene-development.md §四 |
| 每句都对，连起来没推动 | 因果链 | `causal-chain.md` 三测 |
| 台词重复 / 废话多 / 像在传话 | 场景设计：复述观众已知、没有推动者、没有转折 | 先对观众账本与设计卡（`scene-design.md` §一–§三），重做核心一步再改句子；提醒可选冷读（`cold-read.md`） |
| 场面没有画面 / 画面单调 | 可见性 / 场景内容 | 观众能看到所需信息或表演吗；设计卡的静音测试靠什么动作、那个动作与输赢有没有关系（`stage-3c-script.md` §3c.3）；不以有无物件和走位替代判断 |
| 全片都在对抗，累 | 叙事方式单一 | 是否有一场可以用靠近、揭示、积累或余韵 |
| 结尾不成立 / 观众早就知道了 / 场与场之间只是接着发生 | 叙事组织 | `stage-3b-story.md` §3b.2 四个判断：为什么发生、前面怎样改变后面的可能、观众何时知道什么、结尾为何成立 |
| 30 秒塞不下 | 事件承载 | 保留关键事件与表演高光，重排同步 / 先后（`stage-3c-script.md` §3c.8） |
| 中段没劲 / 都在换地方约会 / 高概念立不住 | 机制与两线 | `story-engine.md` §一–§二：前提在中段是否仍产生事件；外部事件与关系是否互相改变 |
| 人物做了不会做的事 / 误会太假 / 突然冷脸 | 触发链 | `story-engine.md` §四：经历 → 触发 → 回应；隐瞒三问 |
| 分集像摘要 / 每集只吊胃口 / 每集靠新误会 | 单集结构 | `episode-design.md` §一、§五 |
| 读着"都对"，但不想看下去 | 观看欲望 | `story-engine.md` §六：观众在哪里得到心动、担忧、惊讶、好笑、释放；正文是否只剩作者的说明与评价、看不见具体行动 |

诊断写一行："问题在 __ 层，因为 __。"

然后**先判改法，再决定改不改**（`execution-contract.md` §修改请求）：
- 用户给了改法，或这一层只有一种合理解法 / 只涉措辞 → 进入 §三，只改那一层及其下游。
- 用户只指出问题，而这一层有两三种真实不同的解法、且解法之间会改变人物、关系走向或后续依赖 → 交付改法选项，不改稿。每种一两句：改什么 / 这场因此变成什么 / 影响后面哪几处；可以推荐并说理由。用户点选后再进入 §三。
- 用户说"你定 / 直接改"→ 自主选一种进入 §三，交付时说明另一种为何没选。

"攻击性太强"这类批评的解法通常不止一种（去掉动作只留对视；保留动作换掉那句台词；保留攻击性但给出理由；把攻击性转给第三方指令），且每种都改变这场戏和两人接下来的关系——这正是要先给选项的情形。

## 三、重写的纪律

修订前按 `story-context.md` 复核采用稿、相关前后文与远处依赖；修订账本只摘要本轮有用信息，不丢弃作为依据的整体故事：

```
修订账本
- 已确认内容：区分硬锁、当前采用稿与确认快照；本次修改授权范围内可改，其余硬锁不动
- 暂定假设：本轮依赖但尚未确认的判断（改了要说）
- 本轮问题：诊断出的层与证据（一行："问题在 __ 层，因为 __"）
- 需要保留的优点：上一版里承载识别性、回应关系、控制过程、母题或吸引力的句子 / 动作 / 画面
- 受影响部分：本轮改动直接牵动的上下文（只改这些）
```

1. **保留上一版；改稿是探索稿。** 对话里保留上一版原文或明确引用；保存项目按 `project-state.md` 先写旧正文快照，探索稿进 drafts，不能仅改文件头。改稿在用户采用前不替换当前采用稿，也不同步到故事正文、分集框架、正典或方法文档；受影响处列为待复核（`story-context.md` §4）。
2. **说明改了什么、解决什么。** 每次重写交付前两行：改动清单（哪几句 / 哪几个动作）+ 对应解决的诊断。
3. **检查有没有失去原稿有效的细节。** 逐条对照账本里"需要保留的优点"：被删的句子 / 动作 / 物件里，哪些承载了识别性、回应关系、控制过程、母题？失去的写明理由；说不出理由的恢复。修到问题所在，同时保留原来的优点，这两件事一起验收。
4. **不把每次重写变成另一个故事。** 事件、人物选择、主控画面不因局部批评而换掉；整体重构属于回到 S3a / S3b；用户已明确要求整体重构时直接在授权范围执行，不再询问同一权限。
5. **定点重写。** 改法已定后，用户批评具体某句时，改那句和它直接牵动的上下句，不顺手重写整场。
6. **达到目标就停。** 没有具体问题证据时，不为"再高级一点""再自然一点"重写；本轮问题解决、优点仍在、锁定未动，即交付。自我润色的第二轮需要新的具体问题，不能以"感觉还能更好"发起。

## 四、示例：为什么"我今天回来了"不能换成漂亮话

示例 04〈行李箱〉的 30 秒里，她指认他反复缺席，他反击"你自己哪天九点前进过这个门"，三秒沉默后她说"我今天回来了"。这句的力量来自它是对上一句指责的回应，并且说出了两人的共同处境：她今天回来了，他今天要走。

假设收到批评“结尾太淡”。先保留“我今天回来了”：它回应对方的指责，不因短而需要换成总结感情的漂亮话。再查问题是否在此前的处境依据、表演显现时间、机位或执行。鞋柜只有他的鞋并不能证明她晚归，不能拿一个含混物件补成事实。只有具体证据显示缺口才改相应层；原 30 秒台词和高光不随诊断示例自动改动。

## 五、场景写作的可选步骤

John August 的场景写法（2007，`screenwriting-traditions.md` §五）可以作为回路里的工具，不必原样走完：这场戏必须发生什么 / 删掉会怎样 / 谁该在场 / 地点还能是哪里 / 有没有意外的可能 / 值得多长 / 三种不同的进入方式 / 在脑子里排演 / 先写潦草版再写正稿。其中"三种进入方式"与"潦草版"最常用：进入方式决定观众带着什么期待进场；潦草版让人物先说话，再决定保留什么。

## 六、与其他文件的关系

- `concept-generation.md` 第 5 步关键场景先行是回路的入口之一。
- `character-scene-development.md` 提供诊断用的人物侧 / 观众侧问题与人物声音问题。
- `causal-chain.md` 三测用于"每句都对但不推动"。
- 成片反馈由 film-director 的 QA 流程处理；本文件处理文本层的批评。
- `preference-ledger.md` 记录用户确认过的偏好，重写时先查是否已有明确偏好。
