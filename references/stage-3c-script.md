# S3c 剧本落地

输入：故事正文、已有完整场景或有效探索片段，以及相关用户硬锁。输出完整剧本页，范围、停靠与保存按 `execution-contract.md`；需要保存时写 `03_script/scene-XX.md`（模板 `templates/script-scene.md`）。剧本页是 A 层 + B 层：允许抽象的只有"导演意图"一栏，动作行与台词必须可拍。

写一场的顺序：3c.0 依据 → 3c.1 设计 → 3c.2 事件轨 → 3c.4 正文 → 3c.5 自检与脚本 → 3c.6 交付（附冷读提醒）。按需方法：`character-scene-development.md` §四–五（对白处境与人物声音）· `causal-chain.md` · `creative-loop.md`（重写）· `research-to-craft.md`（行为与台词缺口）。历史案例与校准记录在 `tests/cases/README.md`，不是写作步骤。

## 3c.0 写前依据（约束）

先按 `story-context.md` 读本场依赖的整体故事、前后场与远处铺垫，提取进场状态、知识边界与后文仍须成立的事实。独立单场只核已有处境；加戏不自动扩展改稿范围。这些依据是**约束**：正文不能与之矛盾。它们不是本场台词的清单——"后文仍须成立"写了三件事，不等于三句台词各还一件；承接能放进动作行就放进动作行，必须由台词交代的，夹进某人要东西的那一句里。

## 3c.1 场景设计（必需；方法见 `scene-design.md`）

写正文前在剧本页 `## 设计` 一节写三样：**观众账本**（观众进场已经知道什么、出处；人物各自不知道什么）→ **核心一步三选一**（本场要改变的那件事，三种真正不同的发生方式，第一种不能是"X 告诉 Y"；选一种并写理由）→ **设计卡**（推动者与战术 / 阻力 / 转折：预期 → 结果 / 弹药 / 静音测试）。

设计卡管这场整体怎么"转"，事件轨管每一行谁的什么变了；设计卡的转折落在事件轨的哪一行，写上行号。短于约 20 s、台词少于 4 句的过场，设计卡可只写一行"推动者 → 转折"；余韵、观察、蒙太奇写"本场不转：理由"。

## 3c.2 事件轨（写台词前的必需产物）

有对话的场或估时 ≥30 s 的场（含无台词场），写第一句台词前填模板的 `## 事件轨`：表上方是人物清单，表里每行是一次变化。**推进只数变化，不数地点**——地点、活动、时间只是变化的属性。

**人物清单**（每人一行）：本场说 ≥3 句的人，以及任何一行变化的主体——**不说话的人也在内**。
- **持续赌注（出处）**：他这一季 / 这一阶段能得到或失去的具体东西（名单、先发、奖学金、家里、工作、关系），从 `ip.md`、故事或分集框架里找，写明出处；找不到就是人物缺口，回 `stage-3b-story.md` §3b.3c 补，不在本场临时编。
- **此刻向谁要什么 / 怕什么 / 为什么是现在**：Mamet 三问（`dialogue-review-sources.md` S6）落到这一场、这个对象。台词先分给这些欲望。

**行**（按正文顺序）：
- **谁 → 对谁**，**变化：进 → 出（类别）**——类别取 得到 / 没得到 / 推迟 / 失去 / 信息 / 关系 / 决定 / 物件 / 地位。进出相同、或与同一人前面某行的"出"相同，都不是变化；"推迟 / 没得到"写代价。"观众"也可以是主体（只改变观众所知）。
- **信息类写清是谁新知道**：人物得知的是观众账本里已有的事时，写"（信息·观众已知；后果：__）"——写得出后果（他因此做了什么新的事），这一行才算变化；写不出，这一行不计为变化，按 `scene-design.md` §一 晚进或删掉。
- **说出口**：这一行里"谁"说出自己要的那句（逐字），或"不说：理由 __；代价 __"（`character-scene-development.md` §一 隐瞒三问）。清单上每个人至少在一行说出口或写明不说的理由与代价。
- **删掉损失**（必填）：删掉这一行，观众少知道或少感到什么；写不出就删这一行或并进上一行。
- **地点（子空间）/ 活动 / 时间 / 锚句 / 估时**：锚句是这次变化在正文里看得见的那一句（逐字），行按正文顺序排；地点沿用上一行写"同上"。只写观众在哪里看见谁在做什么，不写镜头、机位、景别。

**地点只承载变化**：一行换了地点或跳了时间，这一行就必须有变化。**余韵**（没有变化、让刚发生的结果停一下）写"无（余韵：理由）"，只能在原地、不跳时间；余韵合计超过约 10 s 时复核——交给分镜时它最容易被扩成一整条 clip。全场一个地点、一种活动**不是问题**，只要行行有变化；画面单调的疑问按 §3c.3 诊断。

**变化太少**：估时 ≥30 s 的场少于两行有变化时，要么补上真正的变化，要么在表下登记"本场静止：理由"（余韵戏、有意一镜到底、困住 / 对峙 / 等待的压迫感）。全场都有理由不说出口时登记"本场不说出口：理由"。这些是登记在案的例外，不是默认。

**估时**：每行 = 从上一行锚句之后到本行锚句的台词秒数（词数 ÷ 语速；项目有定时按项目，THE ORDER 用 4 词/秒）+ 无台词动作（越过、冲刺、看一眼、换地点，每个都要时间）。总估时写在表下。

**脚本能查什么**：`review_script.py` 逐字核对锚句与说出口的句子（顺序、本人说），比较同一人的前后状态，找出"换了地点 / 跳了时间却没有变化"、变化主体不在清单、"信息·观众已知"却没写后果的行。写得出变化的行脚本一律放行；变化是不是**新的**，由模型按删除测试复核，需要观众视角时提醒可选冷读（`cold-read.md`）。

事件轨对生产侧是**告知**，不是锁定：分镜可以重分段、换子空间、换活动或地点，在方案里写明差异；分镜时长超出总估时 20% 以上只作提醒。短于 30 s、台词少于 4 句的过场可不填。

## 3c.3 "画面单调 / 整场都在一个地方"：先诊断缺什么

用户对画面的疑问是**症状**，不是改法。先用设计卡和事件轨回答缺的是哪一种：

| 诊断 | 缺什么 | 改法方向 |
|---|---|---|
| 一长段没有变化，或 ≥30 s 只有 ≤1 次变化 | **事件** | 在原地补一次真正的变化；或压短、删掉那段 |
| 设计卡写不出推动者或转折：有人报消息、有人听，场末与进场一样 | **推动与转折** | 回 `scene-design.md` §二 重写核心一步：谁出手、对手凭什么不让、预期与结果差在哪 |
| 静音测试不过：人物在做的事与输赢无关（边换衣边听、边吃边谈），变化都在台词里 | **承载输赢的动作** | 让冲突改变正在做的事——被拿走、打断、拒绝、利用；或让一个人进出画面、有人看见 |
| 观众这几十秒新知道的东西都靠嘴说，或观众账本里早已有 | **信息** | 让观众看见一件前面没给过的事（物件、结果、第三人的反应）；已给过的删掉 |
| 行行有变化、静音测试也过，只是一个地点一种活动拍久了 | **都不缺**，是生产侧问题 | 剧本不加段；交 film-director 在分镜里处理，交接说明写一行 |

诊断之后按 `execution-contract.md` §修改请求 给改法：解法不止一种时交两到三种选项，**每个加段或换景的选项都要写出新行本身**（谁：进 → 出、删掉损失），写不出变化的换景不列。"删掉 / 压短"和"不改剧本、交生产侧"都是合法选项。

## 3c.4 写正文

**写法**：按 `scene-design.md` §四 的六条——节拍是出招与回应、信息当弹药、对手不配合、人物主动、演处境不演台词、晚进早出。

**进入**：可从场景梗概、事件、人物或一句可信的台词进入，写出连续片段再审；不先给每句分派策略再让人物填空。卡住时试三种进入方式、先写潦草版（`creative-loop.md` §五）。

**格式**：

```
场 XX 〈标题〉 · 地点 · 时刻
动作行：写清人物在场内做什么及可见可听的结果，读者能连续理解。情绪名称不能替代具体证据；保留速度、幅度和渐变信息。
角色名
    台词。
    （括号补实际有用的表演 / 声音提示；锁定台词不因格式被改字）
```

**动作行**让所选表演可见（"她看着他，眼泪积在下眼睑，抬眼忍住"），保留可观察的速度、程度、渐变与持续；情绪标签不代替表演，音量、语速写在括号里。人物对白可以含歧义，动作行里的"她 / 它 / 这边"要能定位。用户提供或锁定的表演正文完整承接。

**空间**：按需要写清入口 / 出口、起止位置、相关物件、光与声音。影响事件或连续性的物件追踪初态 → 转移 → 末态（谁拿、在哪、由哪个动作改变）；不为所有陈设建表，也不为装饰强加道具或走位——物件与走位只在承载输赢或连续性时写。空间承担隐藏、偷听或关系压力时按 `screenwriting-methods.md` K1 核可见 / 可闻 / 可达。写"观众在哪里看见什么"，不写"用什么镜头看"。

**对白**按连续交流片段写：人物知道什么、为什么此刻这样说、对方如何接收；直接回答、完整长句、有意重复都可以成立，前提是带来了东西。人物措辞缺来处、声音像同一个人、交流靠作者安排时读 `character-scene-development.md` §四–五。句长、停顿、打断与结尾由场景参数（`scene-parameters.md` §二）、角色声音与可用时间决定。可选的张力来源：想说不能说、权力转移、打断、重复变义（回声）、用动作回答、沉默作为台词——是武器，不是配额。

## 3c.5 写完：删除测试、压缩测试、脚本、冷读提醒

"接住上一句"只保证不是交错独白，不保证每句有用。观众听过一次的不再听第二次，重复的台词要删，uh-huh / yeah 这类接话在剧本里很少（Scriptnotes 609，`dialogue-review-sources.md` S5）。写完一段连续对白，交付前直接改自己的稿（审阅用户的稿时只提改法，不改稿）：

1. **删除测试（逐句）**：删掉这句——必要时连同只为回应它而存在的下一句——观众少知道什么、少感到什么？答得出（信息 / 要或拒 / 关系变化 / 笑点或性格 / 必要的调度 / 后文回扣的铺垫）就留；答不出就删，或并进下一句、并进一个动作。观众已知的范围按**真实剧情**算：观众账本、本场前面说过的、画面刚给的；后文会回扣的（`--later`）先确认是不是铺垫再动。
2. **压缩测试（逐段）**：先写出"这段要改变的一件事"，再问最少几句能做到。**简单的事不要复杂化**——一个事实、一个决定、一个邀请，用几轮确认、复述、反问摊开，就是啰嗦。来回多可以成立，条件是每一回合都有人的立场或压力在变（讨价还价、调情、嘴硬）；复述、确认、递话问句不是在变。

记录写在剧本页"对白审阅"下的 `### 删除测试`：`删：「逐字原句」——理由` · `并：「原句」→ 并进哪里` · `压缩：「首句」…「末句」N 句 → M 句；这段要改变的一件事` · `留：「原句」——它带来什么`；什么都没删写 `删：无`。有意回扣前场、观众已听过的句子，写 `留：「原句」——回扣 …`。

**脚本**：剧本页落盘后跑 `python3 scripts/review_script.py 03_script/scene-XX.md --context <前几场> --later <后几场>`（对话内未落盘的剧本页先存到临时文件再跑）。它分开报：**对白连通**（收件人、来回、句长、画外、潜台词支点）· **台词经济**（删除测试记录与正文是否一致，候选句附前文出处）· **复述**（与前几场重合的短语、同一事实——星期、时间、数字——在本场反复出现）· **事件轨** · **设计卡**（在不在、五格齐不齐）。脚本只做可数的部分：判为通过只表示没触发已知问题，语义判断由模型按取向 6 复核并写进同一份 review；来源与 `[推论]` 阈值见 `dialogue-review-sources.md`。

**冷读提醒**：交付剧本页时附一行可选冷读提醒（`cold-read.md`）；用户同意才跑，不擅自跑。

误用信号：为了省字删掉讨价还价、回扣、调情的节奏；把带立场的短句（只叫一声名字、只报一个数字）当接话删；为了"每句有信息"把台词写成交代；把回应全换成沉默。

## 3c.6 交付与连读

每场先交剧本页全文，生产参数与估时说明放在正文后。多场交付前连读：从第一句到最后一个事件按实际呈现顺序只读正文，看前场留下的处境能否带入后场、信息有没有重复或缺失；把各场事件轨的最后一行与下一场的第一行连起来看，连续几场是不是同一种画面、同一种变化、同一种"有人来报消息"的形状。保存的多场剧本可用 `scripts/assemble_script.py` 汇集正文到 `03_script/reading.md`（派生视图，修改仍回各场）。

任务范围提醒：
- **优化单集**：先按 `episode-design.md` §一 答承接 / 进入 / 兑现 / 牵引；已定结尾与前后集事实不动。
- **只优化对白**：交付只改对白的整段全文；事件、设定、场景、结尾不动。范围小不等于改得少：改后每个人都有此刻说这句的理由，两人的声音读得出差别。
- **只诊断**：不交新版本；格式见 `SKILL.md` §默认输出契约。

## 3c.7 重写

收到批评后按 `creative-loop.md` §二诊断层级并判改法：改法未定且解法不止一种时先给改法选项，不改稿；改法已定后按 §三执行（保留上一版、说明改了什么、核对失去的细节、定点改）。批评指向"重复 / 没意思 / 单调 / 像传话"时，**先重做设计卡再改句子**：观众账本里有没有被复述的事、推动者是谁、阻力在哪、转折落在哪一行、静音测试靠什么动作——结构问题靠逐句润色修不好（`scene-design.md` 开头）。未被批评的场景设定保留；但改完内容量或估时变了 ≥20% 时，重做事件轨，在修订账本写"事件轨重核"结论（每行还有变化吗、旧地点与活动还装得下吗）。改稿是探索稿，采用前不同步故事、框架、正典。

## 3c.8 常见失败

| 现象 | 处理 |
|---|---|
| 主角整场在收消息：别人报、他回一句不表态的话 | 设计卡"推动者"写不出他的招——回 `scene-design.md` §二、§三：谁出手、对手凭什么不让、预期与结果差在哪 |
| 上一场告诉了 A，这一场又把同一消息告诉 B | 观众账本已有——B 这边晚进，从他的反应或反击开始；或让告知成为交锋（带消息的人要换什么） |
| 同一个日期、时间、流程在一场里报了几遍 | 只完整说一次，其余交给画面或删；脚本"复述"一项会列出 |
| 转折只靠一句宣布，缺乏可信依据 | 先查人物为什么改变；直接说出决定可以成立，不自动换成放钥匙 |
| 台词都在处理剧情账：回收上一场、给后集埋点、交代流程，没有一个人说出自己要什么 | 回 §3c.2 人物清单，台词先分给欲望；承接进动作行或夹进欲望句 |
| 对白里一件简单的事被拆成几轮确认、复述、递话问句 | §3c.5 删除测试与压缩测试 |
| 为了"画面不一样"加一段新地点或空镜，删掉它观众什么也不少 | 这一行在事件轨里写不出变化——删掉，或在原地补一次真正的变化；余韵只能在原地 |
| 场景只写了地点，整场观众看见的是同一个画面 | §3c.3 诊断：缺事件、推动、承载输赢的动作、信息，还是都不缺 |
| 只有情绪形容，没有可见表现 | 补可观察证据 |
| 台词像同一个人写的 | 查语言经历、交流对象与当前处境（`character-scene-development.md` §四） |
| 结尾总是一句金句 | 判断人物是否真会这样说；允许直说，也允许不总结 |
| 需求明确要喊出来，却写成沉默对峙 | 具体表达方向被默认覆盖；按需求修正 |
| 人物解释制度或工作 | 看听者是否需要知道、人物为何此刻解释；需要就保留，放进要东西的那一句 |
| 事件超出时长承载 | 保留核心因果与高光，重排同步 / 先后；拆 clip 不能增加总时长 |
| 重写后原稿的有效细节没了 | `creative-loop.md` §三 第 3 条 |
