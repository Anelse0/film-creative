# 执行契约（S2 唯一决策源）

模型结合本次原文、历史授权和已有材料理解语义。其他阶段只引用本契约，不再按触发词重新决定范围、保存或确认。

## 先确定交付

- target：S3a 概念 / S3b 故事 / S3c 剧本 / save_only。只运行到用户要求的终点；必要的格式验证不扩展创作交付。分镜、资产计划、Prompt、检查与表演测试属于 film-director skill：记录为越界项并指认交接材料，不在本 skill 内交付。
- entry 与材料：已有故事可进 S3c；局部改写直接进入该稿层级。只补影响本次工作的缺口，辅助表缺失不等于材料未成熟。
- excluded：用户明确不做的阶段。计划与终点不能越过排除项；请求本身冲突时，先交付不依赖冲突的部分，只问必要问题。
- units：scenes（叙事范围）记录于本 skill；shots（镜头限制）与 clips（生成预算）属于生产层，不从场数推导，也不在本 skill 裁决。一个场景不意味着授权写分镜或 Prompt。

## 自主、确认、保存

- autonomy：guided / autonomous。“一次跑完／不用问我”表示自主完成指定目标；不自动确认或保存。“写故事看看”仍只交故事；未指定剧本时不自动补到 S3c。
- 硬锁是用户要求保留的具体内容；当前采用稿是后续工作的版本；探索稿是尚未采用的尝试。采用不等于永远不许修改。新修改请求授权其范围内修订，其他硬锁保留，不再问同一授权。
- save：yes / no / unspecified。本次明确不保存优先；否则本次要求优先于已有约定；均未约定时不落盘。历史 save_policy 可为 never / on_request / after_confirmation / always。确认后自动保存仅在该约定已成立时执行，不因“这个好”临时建立约定。
- confirmation：仅记录用户对本次对应成果的确认及来源。模型推荐、自主选择、脚本通过不是确认；旧稿确认不自动确认新稿，保存草稿不改变确认状态。
- 已有保存约定持续有效，无需每阶段重问。对话探索不创建目录；明确保存候选可在选定前落盘为候选稿，不冒充定稿。

## 何时停

用户要选方向且选择会改变作品时，交付候选后停；授权推荐后继续时可采用暂定方向推进。缺不可替代材料时交付已完成部分与缺口。到达目标即交付，不按 S3a/S3b/S3c 自动增加审批；明确采用停靠协作时按约定停。进入生产的后续决策由 film-director 承接。

## 结构化自检

复杂请求形成结构化记录，简单请求只需一行判断；不要求用户填 JSON。格式见 `templates/execution-record.json`：原始 source；request 的 target、entry、excluded、autonomy、save、units；相关 history；本次 confirmation；hard_locks；planned_stages。未知值留 unspecified，不猜测授权。确认来源不能伪造。

`python3 scripts/route_check.py --record route.json` 只校验判断的结构、保存继承和计划边界，不判断自然语言理解正确性。旧自由文本 CLI 返回“需要语义理解”及退出码 2，不再猜意图。无保存任务可用临时文件检查；实际语义通过任务轨迹与用户指令对照验证。
