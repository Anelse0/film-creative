# 单集与连载：短剧怎样快而不像摘要

短剧 / 多集项目在 S3b 写分集框架、S3c 写单集分场、以及"优化单集"任务时读。单场独立短片不读。季级机制与两条线的判断在 `story-engine.md`；本文件只管一集怎样成立、集与集怎样相扣。

## 一、一集要回答的四件事

写每集之前答，写完再核。答案是具体场面，不是抽象结论。

| 问题 | 要写出什么 | 不算回答 |
|---|---|---|
| **承接**：观众进场时带着什么 | 上一集留下的具体处境（谁欠谁、谁刚知道什么、下一个必到的节点） | "关系升温了" |
| **进入**：本集有效事件从哪一秒开始 | 尽快进入已经在发生的事；开场就在场内，不从起床、走路、寒暄写起 | 固定"前 3 秒必须反转"；为快而删掉理解事件所需的信息 |
| **兑现**：本集推进了什么，观众得到什么 | 一次明确的推进（关系 / 信息 / 位置 / 决定改变）+ 一次情绪回报（心动 / 担忧 / 好笑 / 释放，至少一种落在具体动作或台词上） | 只铺垫下一集；把推进写成人物宣布自己的感受 |
| **牵引**：结尾留下什么 | 由本集事件推出的未决：新的代价、新的选择、新的信息差。观众能说出"因为这个，下一集他不得不……" | 与本集无因果的突发事故；每集结尾都是同一种"被撞见" |

Tierney 谈季末："I don't think the last four minutes of a TV show is the time to give you logistical information" `[一手访谈]`——结尾留给人物的选择与观众的感受，不留给交代。

## 二、分集框架怎么写才不像摘要

摘要式框架的特征：每集写成"空间 / 事件 → 选择与变化 → 结尾"三段抽象陈述，用评价（"关系更近一步"）和作者对手法的说明（"没有靠误会推进"）代替场面。这样的框架读起来齐全，写成剧本时才发现没有一场戏。

写法：

- 每集写**观众看见的一到两个具体场面**：谁在哪里做什么、对方怎么接、结果是什么。能从这一段直接开写分场，才算写到位。
- 一集一个核心事件，最多两个相连场景（2–3 分钟承载不了更多）。
- 集内节拍之间用"因此 / 但是"检查，与集间同样（`story-engine.md` §一）。
- 作者对手法的说明与抽象评价不进框架正文，留在自检；人物的拒绝、不回应、没做成的事写成具体场面即可。
- 每段（arc）的划分依据是**关系状态与外部机制状态同时变化**，不是按集数平均切。

## 三、单集分场（S3c 优化单集时）

1. 先按 §一 答四件事，用一行写下本集的"游戏"：谁想要什么、什么挡着、这集打到哪一步。
2. 开场落在事件里：第一句台词或第一个动作已经属于冲突或靠近。
3. 中段的每一步都改变局面（`stage-3c-script.md` §3c.2 尝试 → 受阻 → 调整 → 代价）；争吵要有具体理由与新信息，不是重复表态。
4. 关键信息通过行动或有理由的对白给出，不由人物宣布（"我已经替你交了罚款"可以说，但要有他为什么现在说、对方怎么接）。
5. 结尾动作或台词由本集事件推出；核对它是否真的给下一集留下不得不处理的事。
6. 已定结尾、锁定台词原样；优化单集不重写全季，不改前后集已定事实。

## 四、平台公式的边界

竖屏短剧行业流传的写法（3 秒钩子、每 20–30 秒一个落点、结尾必卡悬念、"冲突 → 升级 → 反转 → 留钩"）来自平台与培训文章 `[行业文 / 第三方]`，描述的是付费转化下的习惯，不是叙事规律。一位在该行业工作的写手描述创作被"reverse-engineered around data-driven formulas… like doing a fill-in-the-blanks puzzle" `[一手匿名投稿，John August 站]`。

本 Skill 的取用：**快**（尽快进入有效事件、单集有明确回报）是对的；**固定秒数与必反转**不采用。判断标准是 §一 的四件事，不是秒表。电视编剧的传统说法更接近：段落结尾落在一个问题上，下一段来回答它（Scriptnotes 478 及相关讨论 `[一手文字稿]`）——问题要由本段事件产生，答案要真的给。

## 五、诊断

| 现象 | 最可能的原因 | 查 |
|---|---|---|
| 分集框架读着齐全，写不出场 | 写的是结论不是场面 | §二：每集能否直接开写分场 |
| 每集都在吊胃口，观众得不到东西 | 只有牵引没有兑现 | §一 兑现行：这集实际给了什么 |
| 每集靠新误会复位人物 | 误会没有理由与代价（`story-engine.md` §四） | 三问答不出就换事件 |
| 集与集互换无损 | 集间只是"然后" | 前一集留下的代价有没有进入后一集的选择 |
| 中段连续多集只是换地点约会 | 机制消失，两线互不触碰 | `story-engine.md` §一、§二 |
| 结尾像剧情摘要的最后一句 | 用总结代替选择 | 最后一个动作是谁的选择，它推出什么 |
