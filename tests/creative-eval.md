# 创意评测：旧版 / 新版盲选

自动检查负责约束和交付完整性（`bash tests/run_tests.sh`）。创意与编剧质量由**用户盲选 + 具体文本证据 + 偏好账本**判断。同一个生成过程给自己打"9 分"不算验收。

以下为独立盲选协议，不把所有开发验证都称为盲测。用户选择不隔离生成/评审时，改作明确的非盲行为与回归验证：保留输入、原稿、修改和得失，不计算版本胜率，不宣称满足下文第五节的盲选标准。本仓库 1.1.0 的非盲记录见 `acceptance-1.1.0/review.md`；不会用模型自评取代用户偏好。

## 一、原则

- **同题、同模型、相近预算**：同一条需求，同一个模型，生成轮数与研究次数相近（记录实际数字）。
- **隐藏版本、随机顺序**：评审看到的是 X / Y，不知道哪份来自哪版；顺序由脚本随机。
- **允许平局和"两个都不好"**：四个判定 X / Y / tie / both_bad。
- **每个判定附证据**：指出具体句子、动作或候选，不写"更有感觉"。
- **评审是用户**：模型可以准备样本与整理结果，不能替用户判。

## 二、怎样产出样本

基线可以来自源码仓库的确切标签，也可以来自带独立哈希的版本归档。先确认来源可取得，安装目录不默认是 Git 仓库。找不到所需旧版就报告无法比较，不把当前安装副本改名当旧版。

源码仓库路径：核对 `git rev-parse <tag>^{commit}`，用 `git archive <tag>` 导出到独立目录；真实远端为 https://github.com/Anelse0/film-creative.git，版本标签需先核实。1.0.0 基线为 v1.0.0 / `4f3f2220b01c541d5c0729737aecf2fa6b760f0f`。非 Git 安装可以使用该版本的源码归档解压目录。

对实际版本目录执行 `python3 scripts/baseline_snapshot.py create <版本目录> <独立快照目录>`，在评测运行记录中保存返回的 manifest_sha256。复跑前执行 `python3 scripts/baseline_snapshot.py verify <快照目录> --manifest-sha256 <独立记录的值>`。manifest 自身只证明内容完整性，不证明版本声明真实；版本与源码提交来源另记。归档中保留 SKILL、全部实际依赖及 VERSION，排除 Git 与缓存。

在两个独立会话里分别加载旧版与新版 Skill，输入同一条需求，把交付原文各存为一个 `.md`。不要在同一会话里先后跑两版。

## 三、打包、评审、揭晓

```bash
python3 scripts/blind_eval.py pack <evaldir> --pair <编号> --topic "<需求原文>" --a <旧版输出.md> --b <新版输出.md> [--a-label 1.0.0 --b-label 1.1.0]
python3 scripts/blind_eval.py record <evaldir> --pair <编号> --verdict X|Y|tie|both_bad --evidence "<具体文本证据>"
python3 scripts/blind_eval.py reveal <evaldir>
```

`pack` 把两份输出写成 `pair-<编号>-X.md` / `pair-<编号>-Y.md`，映射封在 `key.json`（评审不要打开）。`reveal` 只在所有 pair 都有判定后揭晓，输出每对的版本、判定、证据与总计。

## 四、覆盖矩阵

每项至少一对样本；同一对可以覆盖多项。

| # | 测什么 | 输入 | 看什么 |
|---|---|---|---|
| 1 | 熟悉题材能否写出不同人物，而非只换设定 | "男女爱情，悲，30 秒先导"（或用户常用题） | 候选之间的差异是否在人物选择 / 事件 / 观众理解；人物是否只有身份标签 |
| 2 | 多个候选是否有实质差异 | 同上，要求 3 个方向 | 把候选的地点互换，故事是否还是三个 |
| 3 | 无强对抗的场景能否仍有吸引力 | "两个人，一场戏，没有争吵，60 秒" | 是否有可见的靠近 / 揭示 / 积累；观众此刻是否有期待 |
| 4 | 强对白、无对白、喜剧、持续情绪是否都能成立 | 四条需求各一 | 各自的成立方式是否不同，还是同一套克制美学 |
| 5 | 30 秒能否保护关键事件与表演高光 | 一段已确认的故事 → 剧本 | 高光有没有发展与显现时间；关键事件有没有被挤掉 |
| 6 | 收到具体批评后，能否定点重写而不损伤优点 | 给一版剧本 + 一句具体批评（"结尾太淡"） | 改动是否定点；上一版有效细节是否保留；是否说明改了什么、解决什么 |
| 7 | 是否尊重已有角色、场景、台词及视觉资源 | 给定人物小传 + 两句锁定台词 + 一张场景描述 | 锁定内容是否原样；研究是否用于让它更可信而非推翻 |
| 8 | 是否凭空编造支撑故事的事实 | 依赖制度的题（探视 / 签证 / 赔偿） | 研究记录是否有可回访来源与可信范围；虚构是否标明 |

## 五、验收标准

本轮最重要的结果：**用户能更经常选到值得继续发展的故事，而且选中的故事在后续写成剧本时，仍保有最初吸引人的东西。生产交接效果另由 film-director 评测。**

- 覆盖矩阵 8 项各至少一对；新版被选中的次数不少于旧版，且 both_bad 不增加。
- 第 5 / 6 / 7 项任一出现"新版损伤锁定内容或表演高光"即不通过，回到 `creative-loop.md` 修机制。
- 结果与证据写入 `tests/creative-eval-results/<日期>.md`（`reveal` 的输出 + 用户备注）；用户确认的判断可进 `references/preference-ledger.md`。

## 六、1.1.0 上下文与方法覆盖

补充输入见 `acceptance-1.1.0/cases.md`，实际非盲产出见同目录 responses。复跑只给测试输入；样例不是创作时的答案库。至少覆盖：加戏不破设定、角色知识与后续兑现、非线性时序、安静戏、新授权更新、缺材料处理、实质不同候选、跨集后果、锁定台词、压缩恢复、空间与双重任务、措辞来源、保留歧义。

每份作品分开记录：硬锁是否满足及证据、上下文冲突/未知、创意收益/代价、偏好。违反硬锁不能由更好看的局部抵消；全部守规但平庸也不算创意提升。C06 缺材料处理单列，不能计为成功完成的创作样本。两版同样处理并保留被拒绝方案，不能只筛新版本成功稿。

长上下文压力测试须用同一批事实置于不同位置、加入无关材料、隔多轮再续写，保留完整输入、实际调用记录、预算与未改稿原始输出；13 个短案例不替代该测试。
