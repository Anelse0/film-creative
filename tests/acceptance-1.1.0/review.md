# 1.1.0 Skill Review 与验证记录

日期：2026-09-07。基线：本仓库 v1.0.0，commit `4f3f2220b01c541d5c0729737aecf2fa6b760f0f`。只维护 film-creative，未修改其他 Skill 或本机安装副本。

## 审查结论与实现

| 问题及基线证据 | 影响 | 1.1.0 改动 |
|---|---|---|
| `SKILL.md` 硬规则 6 只有状态/因果原则；`stage-3c-script.md` §3c.6a 主要写后连读，且交付段只点名多场连读 | 单场加戏可能到写完才发现违背整体，或不读远处依赖 | 新增 `story-context.md`，接入 intake、故事、剧本、改稿和恢复：开写前提取整体/本场/远处依据，写后接回后文 |
| `project-state.md` 能分版本，但没有对应的角色知识与事件时点摘记 | 正确文件版本不等于正确角色状态；摘要可能混入探索稿 | 增加三种所知、非线性时序、采用后变化量、否定分支和恢复规则；复用现有状态索引，不增加强制数据库 |
| 概念协议已有差异维度，故事开发操作偏试写/信息排序，缺少把边界用于生成选择的统一入口 | “更有戏”仍可能退化成加灾难、加前史或同一候选换包装 | 新增 `creative-search.md`：从已有关系、未尽承诺、选择后果发展实际正文，比较收益与修订代价 |
| `stage-3b-story.md` 要删不改变当前决定的世界观；概念因果自检把非后果画面直接判为插图 | 会误删暂不触发的正典、观察与母题 | 区分本场取用与正典保存；允许观察、积累与持续状态，保留后续边界 |
| `route_check.py` 接受 S4–S7/performance/raw；附带模板默认 target=S5；旧测试把这当正常 | 代码和独立创意 Skill 的边界相矛盾 | 校验器/模板收敛至 S3a–S3c/save_only，生产阶段只可留作排除/交接信息；新增执行测试 |
| 剧本模板要求 S4 表演块及不存在的 performance-record；因果文件引用不存在的 emotion-performance | 会带入越界流程或读取失败 | 清理残留生产字段/悬空引用；时长不足不再建议靠拆 clip 解决 |
| 旧评测文档引用拆分前的缺失目录与错误远端 | 难以在独立仓库复跑比较 | 更新为当前仓库、确切基线与本次验证状态 |

专业资料及实现对应见 [研究记录](../../references/context-creativity-sources.md)。仅 DOC 采用摘要，明确记录 PDF 读取失败；其他来源注明实际已读范围。

## 文本走查

输入见 [cases.md](cases.md)，实际正文见 [responses.md](responses.md)。由同一维护 Agent 编写并复核，**非盲、无独立旧版生成组、无用户偏好判定**。下表记录具体约束和取舍，不计质量分或版本胜率；失败诱因是合成反例，不能冒称旧版真实输出。

| 案例 | 核对依据与正文证据 | 创作收益与保留的限制 |
|---|---|---|
| C01 世界/身体/后场 | 弟弟站起即跌坐，右脚伤未消失；“给谁看”承接夜里不能打旗语；锁定“天亮再说。”原样；信号旗留在门边，未有救援 | 张力来自他想让姐姐替自己冒险，以及姐姐继续处理现实处境；护灯只产生短暂配合，未宣布和解；灯、盆、旗均来自输入 |
| C02 知识/远处兑现 | 姐姐从抽屉找向下柜而非精准取盒；蓝盒始终未开；她答“开门”，没有揭穿 | 弟弟“找着以后呢”暴露顾虑给观众，不等于姐姐知道藏处；第 4 场告知、第 5 场摊牌仍有作用 |
| C03 非线性 | 8 月 3 日右手拧螺丝、桌下修理，未搬入骨折或信；顾青问“明天几点”只回应当下约定 | 观众可因开场知道离城而读出迟疑；角色程遥不凭空预知，仍期待明天修桌 |
| C04 安静/正文优先 | 小陆要求“等等”，阿宁没有代答；两人继续装箱，无挽留成功或争吵 | 下一句由谁说变成小小的能力交接；戏中台词不是角色挽留，仍可能被观众读成双关；45 秒只是文本目标，未做演员计时 |
| C05 用户修订/故事完整 | 阿岑认识部分字、提前练习；女儿看见后让他先写；家书每周来，最后共同回信 | 从“揭穿”改为看见学习过程，保留体面与共同完成；没有再次请求旧设定的修改批准 |
| C06 未知事实 | 明确无法保证全剧一致，只请求本场前因与后续边界；未造关系/死讯 | 这是缺材料处理，未完成扩写，不计为创意成功样本；独立一场材料充足时应像 C04 直接写 |
| C07 实质多样性 | 关店在三个方向都发生；分别围绕延长使用、分配照顾、纪念对象产生不同结尾 | 三条因果不同；第三条仍使用熟悉合影意象，未宣称彻底摆脱套路；没有替用户选定并写到剧本 |
| C08 跨集后果 | 第 2 集留下三张候选、先问是否重来；第 3 集获得许可后带清唱 | 账号控制与先问承诺未复位；林桥保持主动，成长体现为使用许可而非人格消失。临时缺伴奏是开放新事件，未改第 1 集 |
| C09 定点保真 | 只替换目标句为“我只说饭还热着。”，其余字符保持 | 直接纠正林的过度推断，未谈失约或原谅；已用原稿替换后逐字比较正文 |
| C10 恢复/否定分支 | 妹妹进场已握钥匙，没有重新交接；姐姐离开，妹妹出站，无返程票 | 恢复采用 v3 的方向；两人互相示意对方走的动作有关系内容。这里只有提供的版本原文走查，真实磁盘版本失效由既有 project-state 测试另测 |
| C11 H2/K1/K2 | 玻璃仍透明；走廊既有同事能看见交接进度，阿珂不能绕过共同核对而提前递单，转回共享单子；如实登记、双方签名、帽子仍未找到 | 办交接同时决定今后由谁安排时间；沈文主动担责，阿珂以约定次日共同查询回应，不靠停下工作讲情谊。未伪造制度或开辟新遮挡 |
| C12 K3 | “用餐人数”来自已设语言经历；小满让父亲直接问，他照做；钥匙实际交回 | 正式语感参与听说关系，未遍句套公文；没有由年龄推定方言，女儿搬出未撤销 |
| C13 K4 | 阿衡否认，小岚说“可能”；叙述未断定谁洗杯，也无偷笑暗示 | 她在无法确认时仍选择替对方带早饭，是自己的行动；回应不构成真相证明。保留歧义需要后文继续承接，不能后续无依据落定 |

复核中发现并修正：C01 的初次走查写了输入未提供的“桌沿”，与限定物件清单不符，已去掉；没有把这个中间版本作为旧 Skill 的失败样本。C11 初稿把走廊设为空，玻璃几乎不影响选择；修订测试前提为已有同事等交接单，并重新写递单被看见、回到共同核对的行动。这是同一维护会话中的开发修订，不是固定题目的独立成绩；未验证复杂空间调度。

- 新版：相同命令，60 个 unittest 与 shell 回归通过，含 8 个新增路由测试方法；生产端点逐项拒绝，生产排除项仍可保留，创意入口/保存/自主约束仍有效。

- 没有把规则关键词存在、代码测试通过或这些自编走查当作模型创意提升的因果证据。独立多轮调用、长上下文压力、用户盲选、演员朗读与实际成片效果均未验证。

本版本交付的是可执行的创作/上下文机制、缺陷修正和可复用验收输入；独立质量比较继续使用 [创意评测协议](../creative-eval.md)。旧有效脚本接口、默认不保存、自主不等于确认均保留；生产阶段被校验器拒绝是与既定范围对齐的错误修复。
