# 1.2.1 候选交付格式修订

用户指出 `concept-generation.md` 仍要求十字段候选卡，以及来路/默认地图/推荐和固定选择问题。1.2.0 的简化模板未与这一上游协议同步；校验器还用“至少两个字段行”判断候选，推动 Agent 回填旧卡。

本次统一为标题和连续故事提案。差异从正文呈现，必要时集中比较；创作判断与默认地图在内部使用。移除固定模型风险和“这 N 秒拍什么”栏目。关键事实来源与不确定性仍须处理，但不要求每案填写“无外部事实依赖”或表格。

同步修改概念协议、模板、SKILL 路由、输出格式、研究记录入口与偏好引用，避免同一约束从旁路重新引入。旧字段卡继续可读，不强制用户迁移已有稿。

## 验证

`bash tests/run_tests.sh`：82 个 unittest 与 shell 回归通过。新增 9 个实际解析测试：

- 无分析字段的单正文提案；多个正文提案与集中比较；新旧格式混用。
- 标题/注释/占位符不能冒充正文；未填模板失败；填充新模板通过。
- “人物”开头的普通叙述不被误当字段；正文照搬既有工作示例仍会触发原有检查。
- 新增双候选阅读示意识别为两个候选，且不因缺标签产生告警。

原测试中的 C02（缺内部判断）退出默认检查；C04/C09 仅在用户实际写了相关字段时检查，不因省略字段告警。保留空字段和旧格式回归测试，删除 shell 中旧的“缺标签应告警”预期。

[阅读示意](../examples/concept-prose.md) 是此次编写的格式样稿，不是创作答案库或独立质量评测。脚本识别到正文不等于它就是完整好故事；没有固定字段也不免除 Agent 核对人物、事实、上下文与候选差别的责任。
