# 4.0.0 验收：LLM 正反两序配对（3.8.0 vs 4.0.0-rc1）

用户 2026-09-26 定："先只用 LLM 正反两序配对比较（我在实际生产来完成验收）"；中途定"不用启动 6 个"，对照从 6 组减为 3 组（每个项目一组）。本目录只记录这次 LLM 配对。**它不是效果验收**——效果由用户在实际生产中判断。

## 流程

1. **快照**：
   - 3.8.0 = 提交 `fef425b`（manifest `42b34d1b…`，含 tests/）。
   - 4.0.0-rc1 = 提交 `e4f2f45`（manifest `43025280…`，去掉 tests/ 以免读到案例与夹具；VERSION 文件仍写 3.8.0）。
   - 两份都复制到会话临时目录，写作代理只能从快照读 skill。
2. **写作**：每个任务、每个版本各开一个新上下文的写作代理，共 6 个，同一模型。
   - 提示见 `prompts/writer.txt`，任务见 `tasks/Tn.md`。
   - 用户原话里含"你定，直接写，不用问我"。
   - 可选的独立冷读按 skill 规定不执行，只在交付时提醒。
3. **读取审计**：逐个检查写作代理的工具调用，看有没有打开"禁读"文件（现有稿、生产文件、别的 skill 版本）。
4. **盲评材料**：
   - 两版剧本页只取正文（script-body 标记之间），`blind_eval.py pack` 随机映射成 X / Y，映射封在 `eval/key.json`。
   - `present --order 1|2` 生成两种顺序：顺序 1 = X 在前，顺序 2 = Y 在前。
   - 评审另外只看两份材料：`tasks/Tn-judge.md`（只含用户原话），`ctx/Tn-context.md`（观众在本场之前看过的正文，不含作者说明）。
5. **评审**：两个新上下文的评审代理，每个只负责一个顺序、判全部 3 组，彼此不共享上下文。
   - 提示见 `prompts/judge.txt`，写明"长度不是优点"。
   - 两个顺序判定一致才计胜负；不一致记"不一致（计平）"。
6. **揭晓**：`blind_eval.py reveal`，结果见下文。可数指标（4.0.0 review_script 口径）见 `metrics.json`。

## 已知偏差（读结果前先看）

- **样本小**：3 组，每组每个版本只写一次。同一模型重跑会有波动，单组的胜负不能外推。
- **评审与写作同一模型家族**：两版都由同一模型写，自我偏好对两版一样；位置偏差用两个顺序、两个独立评审抵消。评审仍是 LLM，不是观众。
- **评审维度与 4.0.0 的目标同源**：复述、推动者与转折、静音测试，正是用户批评的"台词重复 / 无意义对白 / 剧情设计弱 / 画面单调"。4.0.0 也正是按这几项设计的，所以评审提示天然对准 4.0.0 的改动方向。
- **已知病例**：T1、T3 是 4.0.0 诊断时用过的场。规则从这些病例里提炼，存在过拟合风险；T5 是唯一的新场，但它的前场（EP04 场 1–3）也是诊断证据。
- **基线快照含 tests/**：3.8.0 写作代理的 T3、T5 各读过一个 EP03 s04 夹具，只用作格式参照；T1 没读。4.0.0 快照不含 tests/。
- **修复在写作之后**：删除测试原句按整句比对的修复，是 4.0.0 写作代理跑完后才做的，不影响评审看到的正文。
- **只比正文**：评审看不到设计卡、事件轨和删除测试，比的是观众会看到的东西；页面篇幅与正文占比见 `metrics.json`，两版正文都只占页面 7–11%。

## 文件

- `tasks/`：`Tn.md` 给写作代理，含可读 / 禁读；`Tn-judge.md` 给评审，只含用户原话。
- `prompts/`：写作与评审提示。
- `outputs/3.8.0/`、`outputs/4.0.0-rc1/`：两版完整剧本页，原样保留，含各自的设计 / 事件轨 / 删除测试 / review。本机绝对路径已换成 `<workspace>/`、`<scratchpad>/` 占位符，其余未改。
- `ctx/`：评审看到的前场正文。
- `eval/`：盲评包，包括 X / Y 正文、`key.json` 映射和 `verdicts.json` 双序判定；`reveal.md` 是揭晓输出。
- `judge/`：两个评审代理的完整报告（顺序 1 / 顺序 2）。
- `metrics.json`：可数指标，只作辅助，不是质量判断。
