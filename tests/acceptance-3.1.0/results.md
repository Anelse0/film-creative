## 二、运行方式

- 输入与标准在规则冻结前固定（`cases.md`）。T1–T6 沿用 3.0.0 输入原样；T7–T9 由**未参与修改的独立子代理**在不看 Skill 的条件下出题（`holdout-tasks.json`），规则冻结后运行。
- 每题每版一个独立 general-purpose 子代理，同一模型，只加载对应版本目录，不联网、不运行脚本、限时 10–15 分钟；T8、T9 各运行两次，全部保留，未挑选。共 22 次运行。
- 评审：`blind_eval.py pack` 随机 X/Y，评审前未打开 key；按 `cases.md` 七条标准逐对写判定与文本证据，再 `reveal`。评审者是维护 Agent 本人，不是用户；两版格式痕迹相近（本次改动不涉及输出格式），但仍不能排除评审者对自己改动方向的偏好。**结论只是"非盲呈现"级别，不能证明用户审美满意度或真实观众效果。**
- 材料：`materials/pair-N-{X,Y}.md`（匿名完整正文），`materials-key.json`（版本对应，单独存放），`blind-verdicts.json`。

## 四、持平、退步、不确定与未完成

- **误伤减少的证据在规则层，不在文本层**：四处误写已确认并改正；但在本次样本里，3.0.0 的输出并没有明显表现出这些误伤（T8 基线也能直接拒绝，T1/T4 基线也没有强加机制）。所以"减少误伤"目前是对规则文本的修正，其实际收益只能在遇到边界情形时才显现，本次样本不足以量化。
- **诊断篇幅**：T2 两版分别为 3,068 / 3,190 字符（约 2,200 汉字，8.1 / 8.2 KB UTF-8；此前误写为“8k 字”，3.1.1 更正），3.0.0 加的"三到五条、能读完为度"没有起作用。未修（本次范围外），记为未解决。
- **评审偏差**：3.0.0 记录中 T6 的评审证据把"每三集回来一次"当作优点，属于本版纠正的频率偏见；本次 T6 的判定依据改为"前一次选择是否改变下一次条件"。
- **样本**：每题每版 1–2 次，方差未知；小样本只提供初步证据。
- **未做**：用户盲选；长上下文、多轮修订；演员朗读与成片。
